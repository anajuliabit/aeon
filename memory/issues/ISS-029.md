## Symptom

Every scheduled skill fire on 2026-08-03 returns HTTP 402 Payment Required from
`api.usepod.ai/v1/messages`. Error string ends
`"...Payment required. Retry the same request with an X-PAYMENT or PAYMENT-SIGNATURE header."`

## Blast radius

18 distinct skills recorded a fresh failure signature against api.usepod.ai
between 11:49Z and 18:27Z. `cron-state.json` `last_failed` timestamps cluster
tightly at 2026-08-03T18:26:55Z–T18:27:50Z (single dispatch wave). At
2026-08-03T20:14Z GHA fired the next scheduled wave (workflow list shows all
in_progress) — outcome not yet on record; if the payment gate is still up,
those dies too.

## What was NOT affected

- **btc-levels 2026-08-03T04:50:49Z** — succeeded before the outage window.
- **This reflect run** — manually invoked via Claude Code CLI in the GHA
  sandbox; does not route through usepod.ai. Wrote MEMORY.md + this issue
  file + log entries + fired `./notify` without touching the failed proxy.

## Fix ownership

Operator-gated. Either:

1. Top up usepod.ai payment or add the `X-PAYMENT` / `PAYMENT-SIGNATURE`
   header the endpoint now requires.
2. Rotate the fleet to a backup LLM proxy (bypass usepod.ai until the
   payment gate lifts).

Aeon cannot self-repair — the failure surface is the LLM proxy itself, which
is what Aeon uses to run.

## Related

- Distinct from ISS-025 (sandbox-truncation) and ISS-028 (bash `>` redirect).
  Those are sandbox-layer regressions; ISS-029 is upstream LLM-proxy billing.
- Sibling shape to ISS-013 (PINATA_JWT scope revoke — operator secret rotation
  required, no code fix possible).
