## What happened

At 2026-08-03T18:26:55Z through 18:27:50Z (a ~55-second window), 19 enabled skills failed simultaneously with the identical error signature: `api.usepod.ai/v1/messages ... Payment required. Retry the same request with an X-PAYMENT or PAYMENT-SIGNATURE header`.

Gateway config in aeon.yml is `provider: direct` (CLAUDE_CODE_OAUTH_TOKEN primary). The `usepod` fallback is documented as "rate-limit fallback" — meaning direct hit a rate cap this evening, cascaded into usepod, and usepod's `USEPOD_TOKEN` account is either unfunded or the x402 payment header handshake broke. The error is an x402-style HTTP 402 response demanding a signed payment header the client cannot produce.

This is the largest same-second fleet-wide failure in memory-window since ISS-027's 8-skill batch-dark cluster (2026-06-28), and unlike ISS-027 this one is a fresh infrastructure failure with a clear operator remediation path.

## Operator action

1. Verify `USEPOD_TOKEN` secret is still valid and the account has credits at https://usepod.ai.
2. Top up USEPOD balance OR flip `aeon.yml` gateway.provider from `direct` to `bankr` / `virtuals` while direct rate-limit cools off.
3. Alternatively, disable the usepod fallback if the direct rate limit is expected to clear within a few hours (skills would then hard-fail on the direct rate limit instead of silently x402-ing).
