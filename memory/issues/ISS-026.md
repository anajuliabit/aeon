skill-evals ran before heartbeat's ~08:00 UTC morning tick on 2026-06-28. The latest log file by filename (`memory/logs/2026-06-28.md`) contains only btc-levels entries from 01:21Z and 05:06Z — heartbeat has not yet logged for today. Pattern `heartbeat|Heartbeat|HEARTBEAT` is absent, producing a FAIL.

This is a timing artefact: heartbeat is healthy (sr=0.54, last_success 2026-06-27T20:22:25Z; pattern `### Heartbeat — 08:18 UTC` and `### Heartbeat — 14:30 UTC` confirmed in memory/logs/2026-06-27.md). The root issue is that skill-evals evaluates the most recent log file by filename, which may be today's sparse early-morning log.

**Recommended fix:** schedule skill-evals after 21:00 UTC so all log-based skills (heartbeat ~08:00, token-alert ~12:00, skill-health ~18:00) have had time to write for the day. Prior evals at 14:48 UTC on Sundays avoided this only because heartbeat had already run; any dispatch before ~08:00 UTC will repro this false-fail.
