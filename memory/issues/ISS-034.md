their first-ever scheduled dispatch window with zero scheduler activity:

- **fork-skill-gap** (aeon.yml:340-346, schedule `"0 21 * * 0"`) — Sunday 8-16 21:00Z

## Investigation notes

Ruled out (from prior heartbeat and skill-health analysis):

- Cron string syntax — both parse cleanly per standard cron (`"0 21 * * 0"` = Sunday
  21:00 UTC; `"30 10 * * 1"` = Monday 10:30 UTC). Verified by direct string inspection.
- Enabled flag typo — both explicitly `enabled: true` in bracketed block form in
  aeon.yml (verified 2026-08-17 20:11Z).
- Slot-wide dark — Sunday 21Z fires: fork-cohort 8-16 19:30Z fired clean (near-slot),
  skill-update-check 8-16 19:11Z fired clean; Monday 10Z fires: unlock-monitor 8-17
  10:37Z fired clean (adjacent slot, mon-batch first-recovery). Neither slot is dark.

Not yet ruled out:

- Scheduler dispatch queue may not scan newly-enabled skills on first-fire path (e.g.,
  requires prior cron-state entry seed, or 1-cycle warmup).
- YAML parser or scheduler config caching may drop entries added within the current
  scheduler-restart cycle.
- Workflow file registration path may require operator-side re-registration for
  first-fire pickup.
