# ISS-018: vuln-scanner missing prefetch script

## Summary

`skills/vuln-scanner/SKILL.md` step 3 invokes `semgrep`, `trufflehog`,
`osv-scanner`, and (when `.sol` files are present) `slither`. None of these
binaries are pre-installed on the GitHub Actions sandbox image, and the
SKILL's sandbox-note already calls out the gap:

> Scanner binaries (semgrep, trufflehog, osv-scanner, slither) are not
> pre-installed in the GitHub Actions sandbox, and outbound pip install /
> curl | sh downloads may be blocked. Operators should pre-cache them via
> scripts/prefetch-vuln-scanner.sh (runs before Claude starts, with full
> network access — see CLAUDE.md prefetch pattern).

The prefetch script does not exist:

```
$ ls scripts/prefetch-vuln-scanner.sh
ls: cannot access 'scripts/prefetch-vuln-scanner.sh': No such file or directory
```

So every vuln-scanner run defaults to attempting in-skill installs, which
fail under sandbox restrictions:

- `pip install --user semgrep` — requires approval; rejected.
- `tar -xzf trufflehog.tar.gz` — requires approval; rejected.
- `./osv-scanner --version` (downloaded ELF binary) — execution requires
  approval; rejected.

The 2026-06-13 superloglabs/superlog scan substituted dep-CVE coverage with
direct `GET /advisories?ecosystem=npm` queries against the GitHub Advisory
Database (functionally equivalent to osv-scanner), but code-flow SAST and
verified-secret scanning had no fallback — both were skipped.

## Impact

- vuln-scanner emits "partial" instead of "clean" or "findings disclosed" on
  every run until the prefetch script ships.
- Code-flaw vulnerabilities (Semgrep's `p/security-audit` + `p/owasp-top-ten`)
  and verified secrets (TruffleHog's `--only-verified` filesystem + git
  history scan) are not detected at all.
- Slither is N/A for most JS/TS targets, so the gap is narrower there, but
  any Solidity repo selected as a target would be unreviewable.

## Fix

Add `scripts/prefetch-vuln-scanner.sh` modeled on the existing prefetch
scripts (`prefetch-xai.sh`, `prefetch-hl.sh`, `prefetch-reppo.sh`,
`prefetch-vibecoding.sh`). The script runs in the pre-Claude phase with full
network access and should install three binaries into `/tmp/bin/`:

```bash
#!/usr/bin/env bash
set -euo pipefail
mkdir -p /tmp/bin

# osv-scanner (single static Go binary)
curl -sSfL -o /tmp/bin/osv-scanner \
  https://github.com/google/osv-scanner/releases/latest/download/osv-scanner_linux_amd64
chmod +x /tmp/bin/osv-scanner

# trufflehog (tarball)
TH_URL=$(curl -sSfL https://api.github.com/repos/trufflesecurity/trufflehog/releases/latest \
  | jq -r '.assets[] | select(.name|contains("linux_amd64")) | .browser_download_url' | head -1)
curl -sSfL -o /tmp/trufflehog.tar.gz "$TH_URL"
tar -xzf /tmp/trufflehog.tar.gz -C /tmp/bin trufflehog
chmod +x /tmp/bin/trufflehog

# semgrep (pip)
pip install --quiet --target /tmp/semgrep semgrep
ln -sf /tmp/semgrep/bin/semgrep /tmp/bin/semgrep
```

Then update `skills/vuln-scanner/SKILL.md` step 3 to call the binaries from
`/tmp/bin/` directly (skipping the in-skill `pip install` / `curl | sh`
attempts) and to record `sources.txt` based on `[ -x /tmp/bin/<tool> ]`
checks. The SKILL already handles missing binaries gracefully via
`VULN_SCANNER_SKIPPED: <tool>` — the prefetch script just changes the
expected outcome from "all four skip" to "all four available."
