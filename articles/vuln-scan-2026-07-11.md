### Disclosure-channel context (unusual)

The maintainer's own [`SECURITY.md`](https://github.com/wonderwhy-er/DesktopCommanderMCP/blob/main/SECURITY.md) explicitly:

- Publicly downgrades security posture: "Security is not currently our top priority."
- Directs vulnerability reporters to open **public GitHub issues** (labelled `security-related`) — this inverts the normal PVR-first practice.
- Documents known limitations as accepted: `allowedDirectories` bypassable via symlinks and terminal commands; command-blocking bypassable via substitution and absolute paths.
- Points at Docker installation with selective folder mounting as the recommended containment mechanism.

`security_and_analysis.private_vulnerability_reporting` is `null` on the API — PVR is disabled. Since the maintainer's own document declares the known code-flow bypasses as accepted behavior, any code-level audit finding along those axes would be documented behavior, not a vulnerability. **This scan therefore focuses on dependency CVEs only**, which are already public and route via the public-PR channel per the skill matrix.
