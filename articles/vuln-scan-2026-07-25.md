## candidate findings (3 total, all triaged out)

### #1 — quick-xml 0.38.4 → RUSTSEC-2026-0194 + RUSTSEC-2026-0195

- **class**: DoS. CVSS 3.1 `AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`
- **advisories**: quadratic runtime on duplicate-attr check (0194) + unbounded namespace-decl allocation in NsReader (0195)
- **fix**: 0.41.0
- **dep chain**: `rust-s3` + `aws-creds` (both git-pinned to `tlongwell-block/rust-s3@c9fce36` fork) → quick-xml 0.38.4. rust-s3 is used by `buzz-media`, `buzz-relay`, `buzz-agent` for S3 object storage
- **triage**: **DROP — maintainer-managed**. `deny.toml:12-21` explicitly ignores both advisories with reasoning: "trusted-input XML only; no upstream fix available yet". buzz's S3 endpoint is operator-configured (own bucket / MinIO), so the XML parser only sees responses from a trusted backend. Reachability would require the operator's S3 backend to be attacker-controlled (assumed trusted).

### #2 — quick-xml 0.39.4 → RUSTSEC-2026-0194 + RUSTSEC-2026-0195

- **class**: same as #1
- **fix**: 0.41.0
- **dep chain**: `mesh-llm-host-runtime` (git pin `Mesh-LLM/mesh-llm@v0.73.1`) → `iroh` → `netwatch` → `netdev` → `plist` → quick-xml 0.39.4. `plist` parses local macOS system `.plist` files during network interface discovery (netdev).
- **triage**: **DROP — unreachable from untrusted input**. Same `deny.toml:12-21` ignore covers this. The plist parser only sees OS-generated interface metadata; no attacker input reaches it.

### #3 — opentelemetry_sdk 0.31.0 → GHSA-w9wp-h8wv-79jx

- **class**: DoS (unbounded memory in W3C Baggage propagation). CVSS 3.1 `AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L`. GHSA severity **MODERATE**. CWE-770.
- **fix**: 0.32.1
- **dep chain**: `mesh-llm-host-runtime` (git pin, same as #2) → opentelemetry_sdk 0.31.0. buzz workspace ALSO pulls opentelemetry_sdk 0.32.1 directly for its own tracing — so the vulnerable 0.31.0 code path lives inside mesh-llm's internal LLM-inference tracing, not the relay's HTTP request-handling.
- **triage**: **DROP — narrow attack surface + not shippable as PR**. The vulnerable Baggage propagation is invoked on `TraceContextPropagator::extract` against incoming carrier headers. In buzz-relay, incoming HTTP baggage is processed by opentelemetry 0.32 (workspace-declared). The 0.31 code lives inside mesh-llm's model-inference tracing pipeline, which processes operator-controlled model requests — not attacker-controlled headers. Fix requires bumping the `mesh-llm@v0.73.1` git pin to a version whose deps use opentelemetry 0.32+ — a PR shipping a hand-edited Cargo.lock would break the git-tag pin (same anti-pattern as tirth8205 uv.lock case). Not in `deny.toml` yet; maintainer's own cargo-audit run in CI will surface it naturally.

## code-audit spot check (partial — no semgrep)

Hand-read the two highest-attack-surface crates. No confirmed findings.

- **`buzz-workflow/src/executor.rs:735-815` — SSRF check on `call_webhook`**: textbook-correct. Resolves host via `to_socket_addrs()` in `spawn_blocking`, rejects any private/reserved IP, then pins DNS via `.resolve(host, safe_ip)` on the reqwest client to defeat DNS-rebinding TOCTOU. Also disables system proxy (`.no_proxy()`) and redirects (`Policy::none()`) — a redirect to an internal host would bypass the pre-resolve check. Response size capped at 1MB.
- **`buzz-core/src/network.rs:46-95` — `is_private_ip`**: comprehensive. Blocks IPv4 private/loopback/link-local/broadcast + CGNAT `100.64.0.0/10` (cloud-metadata risk on AWS/GCP) + benchmarking `198.18.0.0/15` + IPv6 ULA/link-local/multicast + documentation `2001:db8::/32` + IPv4-mapped IPv6 (recursive) + NAT64 well-known + local-use + legacy SIIT IPv4-translated + Teredo `2001::/32` + 6to4 `2002::/16`. Every case tested (`crates/buzz-core/src/network.rs:97-`).
- **`buzz-auth/src/nip42.rs` — NIP-42 challenge/response**: challenge is 32 CSPRNG bytes hex-encoded (256 bits); event verified via `buzz_core::verify_event` (Schnorr); relay URL normalized (localhost/::1 → 127.0.0.1, trailing slash strip); ±60s timestamp window via `abs_diff`.
- **`buzz-auth/src/nip98.rs` — NIP-98 HTTP auth**: kind 27235, Schnorr sig, ±60s window, URL match (no loopback aliasing — deliberately, to preserve multi-tenant host-binding integrity, documented in-line at `nip98.rs:138-144`), method case-insensitive, SHA-256 payload-tag binding to body when both are present.

Nothing surfaces at read-level. A full semgrep pass would need a real runtime, not this sandbox.
