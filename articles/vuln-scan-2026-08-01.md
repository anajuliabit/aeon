## Code audit (hand-review via 3 parallel Explore agents)

Attack-class matrix — every finding was reviewed against the surrounding code before triage:

### Auth / capability / OAuth
- Signed tokens: `alg` pinned to `["HS256"]` in `compactVerify`; `constantTimeEqual` (Node `timingSafeEqual` with length pre-check) used throughout `src/auth/`.
- Source-auth: `HMAC-SHA256` over canonical `${method}\n${path+query}\n${body}`, ±5min window, `ReplayDedupe` per signature. `x-signature` array/type-confusion closed at `http.ts` `front()` before handlers see it.
- Capability tokens: audience-pinned; scope re-verified via `authorizesCapabilityScope`; `triggered` capabilities rejected on consent-affecting routes.
- OAuth (`src/connectors/oauth.ts`): `state` is a sealed signed token with `principalId`/`redirectUri`/`nonce`/`issuedAt`, 10-min max age, nonce-deduped, `redirect_uri` for token exchange comes from the sealed state (not the callback URL), Google `hd` claim validated when `accountType==="company"`.
- Portal OIDC (`plugins/portal/src/oidc.ts`): PKCE required, id_token nonce/aud/azp verified, subject-mismatch check against userinfo.
- CSRF: portal enforces `sameOriginRequest` on all state-changing POSTs; agent API state-changers require custom `x-agent-capability` header (forces CORS preflight).
- Front-door refuses to boot in prod without distinct `CAPABILITY_SECRET`/`PORTAL_IDENTITY_SECRET`/`CORE_SIGNING_SECRET` each ≥32 chars.

### Injection / SSRF / traversal
- **Command exec:** `aws/microvm-agent/agent.mjs` exposes an unauthenticated `/exec` — but by design; the microVM is per-request-Lambda-scoped and only reachable from the platform core (`src/deploy/aws-deploy-provider.ts`). All shell-building paths use `shq()` quoting or regex-validated inputs. No `shell:true`, no template-string exec.
- **SSRF:** `credential-broker.ts` is https-only, host-pinned via `endsWith(`.${p}`)` with mandatory dot boundary, method+path allowlisted, `redirect: "manual"`, caller headers stripped to `accept/accept-language/content-type/user-agent`. `git-http-broker.ts` reuses the same controls. `skills/pack-fetcher.ts` pre-resolves DNS, rejects private-network IPs, pins the resolved IP set via `http.curloptResolve`, disables redirects — no TOCTOU DNS rebinding. Egress proxy (`deploy/egress-proxy/envoy.yaml`) fails-closed on Lua httpCall failure, statically denies metadata authorities, strips attacker-supplied `x-egress-upstream-address`, and re-checks the resolved IP in `src/egress-authz-main.ts` against link-local/metadata blocklists before returning a specific IP to Envoy's `ORIGINAL_DST`.
- **Path traversal:** no route reads/writes filesystem paths from raw request input. `admin/files.ts` uses opaque artifact ids through `deps.files.get(id)`; upload names pass `safeAttachmentName` (basename after backslash-to-slash). `deploy-fs.ts` `normalizeRelPath` rejects absolute paths, `.`/`..`, NULs, and `.git` metadata.
- **SQL:** all `postgres-*.ts` use `$1..$N` placeholders. Only interpolation is developer-controlled identifiers (hardcoded column lists, `${table}` from constants).
- **Template injection:** no `eval`/`new Function`/`vm.runIn*` on external input in production paths. `secret-drop.ts` HTML built with `escapeHtml()` + `JSON.stringify()` for a script-context `dropId` whose route regex `[^/]+` blocks `</script>` construction.
- **Prototype pollution:** no `_.merge`/`deepmerge`; route bodies destructured into typed shapes.

### Secrets + crypto
- Committed secrets: **zero.** Every real-format grep (`sk_live_`, `AKIA`, `ghp_`, `xoxb-`, `-----BEGIN * PRIVATE KEY-----`, `hooks.slack.com/services/…`) returned no hits. All `secret =`/`password =` matches were test fixtures (`"test-signing-secret".repeat(3)`, `"AKIA_BOB_GENERAL"` etc.). Repo has a single "Fresh repo history" commit (`57b5191`) so `git log -p -S` covered the full history in one pass.
- Crypto: `src/util/crypto.ts` `constantTimeEqual` correct. `aes-256-gcm` (authenticated) in `connectors/connector-client-store.ts`. No `createCipher`/`aes-*-cbc/ecb`/`md5`/`sha1-for-security` in `src/`. Only JWT lib is `jose` with algorithm-pinned `compactVerify`. `Math.random()` in `src/` limited to non-security uses (emoji sample, tmp-filename suffix).

## Candidates reviewed & dropped

Six low/medium candidates were surfaced across the three agents; each was dropped in triage:

1. **PKCE not enabled for confidential-client OAuth** (Google/GitHub/Slack/Notion/Linear/Dropbox) — dropped: `state` is already signed + nonce-deduped + `redirect_uri`-bound, defense-in-depth not a defect.
2. **Capability tokens in URL query strings** (`?t=` on `/drop/:id/form`, `?token=` on git deployment routes) — dropped: audience-restricted, short-lived, deliberate for git clients that can't do Bearer.
3. **`brokerCredentialAuthHeader` empty-scheme concatenation** — dropped: intended for API-key headers, misconfig risk not code flaw.
4. **In-memory `consumedStates` LRU in portal** — dropped: replay requires attacker to also hold the HttpOnly `portal_oidc_tmp` cookie.
5. **`x-admin-actor` header trusted when source-auth present** — dropped: only reachable in non-production or non-`requireSignedPortalIdentity` deployments; production gate at `server.ts:250-275` refuses admin routes without portal identity. Also requires attacker to already hold `CORE_SIGNING_SECRET`, which is server-side infra and grants full admin-of-anyone regardless.
6. **Legacy signed-token accepts both base64url and hex encodings** — dropped: same underlying HMAC, not exploitable.

Plus two from the crypto pass:
- **Non-constant-time HMAC compare in `skills/skill-store.ts`** — dropped: both operands computed server-side against stored data, no remote signature-submission oracle exists.
- **Unverified Google id_token used for `hd` allow-list** — dropped: id_token comes back over TLS from Google's token endpoint via server-to-server call with `client_secret`; exploiting requires MITM of Google's TLS.

## Verdict

**Clean audit — 8 candidates reviewed, 0 confirmed.** Partial-scan (npm-audit + hand-audit; semgrep/trufflehog/osv-binary blocked by ISS-018 sandbox family).

qm is a notably well-engineered auth surface: algorithm-pinned JWT, timing-safe MAC compare, replay-dedupe with signed nonces, host-pinned credential broker with header allowlist, PKCE on portal OIDC and the one OAuth provider (`x`) that requires it, egress-proxy with fail-closed Lua authz, and IP-pinned outbound-fetch that closes DNS-rebinding.
