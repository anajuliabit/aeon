## Candidate findings

### 1. `@opentelemetry/core@1.30.1` — GHSA-8988-4f7v-96qf

- **Advisory:** [GHSA-8988-4f7v-96qf](https://github.com/open-telemetry/opentelemetry-js/security/advisories/GHSA-8988-4f7v-96qf) — Unbounded memory allocation in W3C Baggage propagation
- **Severity:** MODERATE (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L) · DoS-only
- **CWE:** CWE-770 (Allocation without limits)
- **Fixed:** 2.8.0
- **Reachability:** transitively pulled by `lighthouse@13.4.0 → @sentry/node@^9.28.1 → @opentelemetry/core@1.30.1`. `lighthouse` is a package.json devDependency, but the `bundle` script bakes runtime deps into `build/src` via rollup, so the code path is shipped.
- **Triage:** DROP. Sentry SDK is a no-op without a configured `SENTRY_DSN` — chrome-devtools-mcp does not configure one, so the W3C Baggage-parse path is unreachable in default usage. MCP tool calls do not carry baggage headers; Puppeteer's HTTP handling is the browser's, not Sentry's. Moderate DoS-only, fix requires an upstream chain bump (lighthouse → sentry v10+). Google's own Dependabot tracks the same tree.
- **Would-be-embarrassed test:** yes. Not filing.
