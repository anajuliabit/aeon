## Code-flaw hand-audit

**Coverage:** every `exec.Command*` call site (74 in non-test code), every `os.Readlink`/`os.ReadFile` on attacker-influenced paths, every `fmt.Print*` / `Printer.Print*` on user-influenced strings, every path-construction site, plus `install.sh`.

**Verdict:** 0 confirmed findings. Defensive posture is unusually strong for a devtool this young:

- **argv-injection defense** — `isValidContainerID` (`internal/proc/container.go:73`) rejects leading dashes and non-`[A-Za-z0-9._-]` chars before any `docker inspect` / `podman inspect` / `crictl inspect` / `nerdctl inspect` call; `isValidServiceLabel` (`internal/target/name_freebsd.go:22` + `name_darwin.go:22`) enforces `^[a-zA-Z0-9][a-zA-Z0-9._-]*$` on service names before `service <name> status` / `launchctl print system/<label>`. `filepath.Abs` is used defensively in `internal/target/file_darwin.go:13` and `file_freebsd.go:13` with an inline comment explaining leading-dash paths can't be parsed as `lsof`/`fstat` options once absolute.
- **`--` separator discipline** — `docker inspect ... -- <id>`, `podman inspect ... -- <id>`, `systemctl show ... -- <svcName>` all use the argv terminator. Container IDs that skip `--` (crictl, nerdctl positional pattern) still pass through `isValidContainerID` first.
- **terminal-escape sanitization** — `output/sanitize.go` provides `SanitizeTerminal` / `SanitizeTerminalLine`; `output/printer.go` wraps `fmt.Fprintf` and auto-runs `SanitizeTerminalLine` on every `string`/`[]byte`/`error`/`fmt.Stringer` arg. Only the custom `ansiString` type (defined in `output/colors.go` and used exclusively for internal color escapes) passes through unmodified. Applied broadly across `internal/output/standard.go` (process command, cmdline, user, container, service, working dir, git repo/branch, health, chain names, source description, socket lines, thermal state, file paths, fd list, socket info) and mirrored in `internal/tui/data.go` for the TUI. `output/safe_writer.go` gives a `SafeTerminalWriter` wrapper for direct `io.Writer` uses.
- **container-ID provenance** — every `crictlInspect(id)` / `dockerLikeHostPID(id)` / `lxdLikeHostPID(id)` receives an id sourced from the corresponding runtime's own JSON listing (`crictl ps -o json`, `docker ps --format`, etc.), not from unfiltered user input.
- **no network attack surface** — zero `net.Listen` / `http.ListenAndServe` in non-test code. Pure CLI + TUI, no daemon.
- **no privilege escalation vectors** — zero `setuid` / `setgid` in non-test code; witr runs as the invoking user and reads `/proc/*` with that user's privileges.
- **no unsafe deserialization** — no YAML unmarshal of user input, no text/html template, no gob decode.
- **plist parsing** — `parsePlistXML` in `internal/launchd/plist.go:172` uses `encoding/xml`, which does not resolve external entities by default (no XXE risk in Go's stdlib xml).

## Advisory notes (not vulnerabilities — logged for maintainer awareness only, no PVR filed)

1. **`SanitizeTerminal` uses `unicode.IsControl(r)`** — that check catches Unicode category Cc (C0/C1 controls, ESC 0x1B, DEL 0x7F) but not category Cf (BiDi override U+202E, zero-width joiner U+200D, zero-width space U+200B, etc.). A hostile process that sets its own name via `prctl(PR_SET_NAME)` to include U+202E can flip the visible order of that field in the TUI's process table. Threat is limited to visual spoofing — no code execution, no privilege escalation — and the primary ANSI-escape threat is fully covered. Defense-in-depth suggestion: extend to `unicode.IsControl(r) || (r >= 0x200B && r <= 0x200F) || (r >= 0x202A && r <= 0x202E) || (r >= 0x2066 && r <= 0x2069)` or use `unicode.IsPrint(r)` inversion. Below the bar for a PVR.
2. **`install.sh` downloads release binary without SHA256 verification** (line 78 — `curl -fL "$URL" -o "$TMP"`). Standard `curl | bash` posture; supply-chain hardening rather than a bug — verifying against a `checksums.txt` served from the same release would raise the bar. Below the bar for a PVR.
