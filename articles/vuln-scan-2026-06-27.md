## Confirmed findings & disclosure routing

### Code (1) — routed to `.pending-disclosure/` (no safe channel)

**[HIGH] CWE-88 argument injection in yt-dlp subprocess call**

User-supplied URL is passed to `yt-dlp` as the final argv element with no `--`
separator, allowing a caller of the library API to inject yt-dlp flags
(`--exec`, `--cookies-from-browser`, `--postprocessor-args`, etc.). Combined
with the currently-pinned `yt-dlp 2025.5.22` (5 known CVEs), this is RCE.

- **Channel:** drafted but **not published** — PVR is **disabled** on the repo
  (HTTP 403 on `POST /repos/.../security-advisories/reports` —
  "Repository does not have private vulnerability reporting enabled"), and
  SECURITY.md offers no fallback contact. Draft saved to
  `.pending-disclosure/Panniantong-Agent-Reach-2026-06-27T161800Z.md` for the
  operator to escalate out-of-band (Twitter/X `@Panniantong`).
- **Patch:** one-line fix (insert `"--"` before `url` in the argv list).
  Not pushed to any public branch.
